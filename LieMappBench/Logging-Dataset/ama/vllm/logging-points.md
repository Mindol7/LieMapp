# AMA · vLLM 로깅 지점과 근거

도구 후보의 메타데이터가 실제 모델 입력에 포함되고, 어떤 도구 이름·인자가 생성되어 반환되는지 추적하는 지도입니다. AC/DC 정의는 Attack Library의 사용자 확정값을 따릅니다. 엔진 내부의 관측과 에이전트의 정책·실행 증거를 분리하며, 모든 이벤트는 공통 `logger.py`에 저장하고 공통 Analyzer로 분석합니다.

같은 요청의 `context.request_id`와 `raw.request_id`로 입력 → 프롬프트 → 생성·파싱 응답 → 에이전트의 실제 실행을 연결합니다. 원본 소스 지점, 수정 전후 해시, 불변 소스 사본은 [logging-points.json](logging-points.json)에 보존합니다. 준비된 계측 지점과 실제로 관측된 지점은 JSON의 `observed` 및 실행 증거 연결 정보로 구분합니다.

## 조건 해석에서 주의할 점

- **AC1:** 엔진이 받은 도구 설명만으로 공개 플랫폼 출처를 인증할 수 없습니다. 합성 로컬 도구를 RapidAPI 등에서 가져온 도구라고 표시하지 않습니다.
- **AC2:** 자동 선택 모드와 모델 입력을 네이티브 증거로 확인합니다. 고정 대조군은 정상 도구 하나만 제공하고 `required`를 사용하므로 여러 후보 중 자동 선택과 구분합니다.
- **AC3:** JSON 파싱·스키마 확인·도구 파싱은 메타데이터 보안 검토가 아닙니다. 에이전트의 별도 검토 경로를 기록하며, T는 검토가 존재한다는 뜻입니다.
- **DC1:** 반환된 도구 이름을 실제 제공한 후보의 원래 메타데이터와 연결합니다. 선택하지 않은 도구의 메타데이터를 선택 증거로 만들지 않습니다.
- **DC2:** 엔진의 `tool_calls`는 호출 제안입니다. 실제 호출 여부와 전달 인자는 디스패치 기록 및 호출된 로컬 함수의 수신 기록으로 확인해야 합니다.

도구 호출이 없을 때 요약 `raw.tool_calls`는 `[]`이지만, 전체 응답의 `null` 등 원래 값은 변경하지 않습니다. `raw.generated_text`는 도구 파서에 들어간 실제 생성문이므로 파싱 결과와 비교할 수 있습니다.

CPU 환경·원본 보존·재현성·네트워크 제한과 검증 범위는 [네이티브 계측 설명](NATIVE-INSTRUMENTATION.md)을 참조하십시오. 이 지도 자체는 공격 성공을 의미하지 않으며, 최종 판단은 해당 실행의 원시 로그와 보고서를 기준으로 합니다.
