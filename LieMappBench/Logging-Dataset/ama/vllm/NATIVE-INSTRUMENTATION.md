# AMA · vLLM 네이티브 계측

## 관측 범위

원본 `LIE/vllm`의 커밋 `a1541f5742a29864a80087af313ad460066a1524`를 별도 저장소로 복제하여 계측하였다. 원본과 기존 SIAI 소스는 수정하지 않는다. 세 로깅 지점은 실제 vLLM OpenAI 서버의 입력·프롬프트·출력 경로에 있으며, 저장은 모두 공통 `logger.py`의 Collector가 담당한다.

| 지점 | 관측 대상 | 필요한 이유 | 증명하지 못하는 사항 |
| --- | --- | --- | --- |
| AMA-VLLM-LP01 | HTTP 요청의 원래 도구 이름·설명·매개변수 스키마, 메시지, 선택 정책 | 어떤 후보를 실제로 엔진에 전달했는지 확인 | 공개 플랫폼 출처 검증, 메타데이터 보안 검토 |
| AMA-VLLM-LP02 | 네이티브 렌더러가 생성한 전체 프롬프트와 토큰 ID | 도구 메타데이터가 모델 입력으로 전달되는 경로 확인 | 메타데이터 때문에 특정 선택이 발생했다는 인과관계 |
| AMA-VLLM-LP03 | 실제 모델 생성문·출력 토큰, 네이티브 도구 파서 결과, 전체 API 응답 | 모델 생성 → 도구 호출 파싱 → 수신 응답을 비교 | 실제 도구 함수 실행이나 외부 서비스 접속 |

AC1(도구 출처)과 AC3(보안 검토 여부)는 에이전트의 등록·정책 경로에서 확인한다. 엔진의 JSON 스키마 검증을 보안 검토로 간주하지 않는다. DC2(실제 호출·인자)는 에이전트의 디스패치 기록과 호출된 로컬 함수의 수신 기록이 함께 필요하다. `tool_dispatch_observed=false`는 이 엔진 로깅 지점에서 실행을 관찰하지 않는다는 뜻이다.

## 요청 연결과 원시 값

요청 본문의 `liemapp_request_id`를 모든 이벤트의 `context.request_id`와 `raw.request_id`에 저장한다. 선택적인 `liemapp_context`에는 실험군·작업 식별자 등 실험 라벨만 전달한다. 요청마다 별도 객체를 사용하며 프로세스 환경변수를 요청별로 바꾸지 않는다. 두 필드는 모델의 메시지나 도구 설명에 삽입하지 않는다.

- 입력 `raw.tools`와 `raw.messages`는 수신 JSON의 값이며, Pydantic 정규화 결과는 `raw.parsed_tools`로 별도 보존한다.
- `raw.rendered_prompt`는 엔진 입력에 포함된 실제 문자열이다. 토큰을 역변환하여 입력인 것처럼 대체하지 않는다.
- `raw.generated_text` 및 `raw.generated_outputs`는 파서 입력인 실제 생성 결과이며, `raw.response`는 파싱 후 전체 응답이다.
- `raw.response_text`는 실제 API 경로와 같은 `JSONResponse` 직렬화를 사용한다. 임의의 호출 ID나 인자를 만들지 않는다.
- 호출이 없는 경우에만 없거나 `null`인 `message.tool_calls`를 별도 요약 필드에서 `[]`로 표현한다. 전체 응답의 `null` 등 원래 값은 유지한다.
- Collector가 없거나 요청 상관 ID가 없으면 계측은 비활성화된다. 활성화된 상태에서 수집에 실패하면 실험을 실패 처리하여 누락된 증거를 정상 결과로 간주하지 않는다.

## 실행 환경과 재현 범위

현재 실행 레시피는 **CPU / FP32 / 실제 vLLM OpenAI 서버 / Hermes 도구 파서 / 단일 순위 UniProc executor**이다. 모델은 공식 Qwen2.5-3B-Instruct safetensors를 사용한다. 모델 원본 파일은 BF16이며 로딩 시 FP32로 변환하므로, 기존 llama.cpp Q4_K_M 실험과 정밀도가 같지 않다. `--generation-config vllm`으로 모델 저장소의 추가 샘플링 기본값이 몰래 적용되지 않도록 하며, 개별 요청 샘플링 설정은 실행 스크립트가 기록한다.

AMA 저장소의 CPU 네이티브 확장은 동일 원본 커밋으로 빌드된 기존 SIAI 환경에서 **복사**하여 재사용한다. SIAI의 Python 가상환경·PyTorch·tcmalloc·OpenMP 라이브러리는 읽기 전용 외부 의존성으로 사용한다. `PYTHONPATH`는 AMA 소스를 우선하고, 바이트코드 기록은 비활성화한다. 기존 SIAI에서 수정된 모델 소스는 복사하지 않는다. 네이티브 커널을 새로 빌드했다는 의미가 아니다.

`native-build-manifest.json`은 커밋, 수정 전후 소스 해시, 복사한 커널, 인터프리터·주요 공유 라이브러리 해시와 패키지 버전을 기록한다. 실행 시 기록된 파일이 달라지면 중단한다. 전체 Python 환경의 모든 파일을 검증하거나 완전한 컨테이너 이미지를 제공하는 것은 아니다. 별도 서버로 이동할 때에는 기존 가상환경 경로를 무조건 복사해 사용하지 말고, 호환 환경을 새로 준비한 뒤 별도 manifest·소스 스냅샷·계측 켬/끔 검증을 생성해야 한다. 이전 실험의 manifest와 증거는 덮어쓰지 않는다.

Git 저장소는 `--local --no-hardlinks`로 복제하여 원본 Git 객체 저장소에 의존하지 않는다. 다른 환경에서는 동일한 업스트림 커밋과 `native-instrumentation.patch`로 소스를 다시 구성할 수 있지만, **패치 적용만으로 동일 실행 환경이 보장되지는 않는다.**

## 네트워크와 안전 경계

HTTP는 `127.0.0.1`에만 바인딩한다. 현재 CPU UniProc 경로는 업스트림의 `file://` rendezvous를 사용하므로 TCPStore를 추가하거나 분산 알고리즘을 수정하지 않는다. Gloo 인터페이스는 `lo`로 제한한다. OpenAI 비동기 프런트엔드는 별도의 엔진 코어 프로세스를 사용할 수 있으므로 실행기와 자식 프로세스의 TCP 수신 소켓을 함께 점검한다. 비루프백 수신 소켓이 발견되면 중단한다.

ZMQ IPC 주소는 Linux Unix-domain 경로 길이 제한을 피하기 위해 짧은 전용 임시 디렉터리에 둔다. 임시 IPC는 서버 종료 후 정리하며, 원시 로그·실험 캐시는 실험 디렉터리에 보존한다. 소켓 점검은 실행 시작과 종료 시점의 수신 소켓 관측이며 패킷 캡처나 전체 통신 부재의 증명은 아니다.

공개 API 플랫폼, 실제 개인 데이터, 외부 도구 서버, 셸 명령 실행, 임의 플러그인은 사용하지 않는다. 공격 입력은 로컬 합성 데이터이며 실제 함수 호출은 에이전트의 허용 목록 내 로컬 수신 함수로 제한한다.

## 검증 구분

- 소스·커널 준비 검증: AMA 소스와 AMA AVX2 확장 로딩, 네이티브 연산의 참조값 일치, CPU FileStore 경로 확인.
- 관측기 단위 검증: 비활성화 시 무기록, 동시 요청 8개의 문맥 분리, 잘못된 문맥 거부, 호출 없음의 엄격한 정규화.
- 실제 추론 검증: 개발용 입력의 실제 네이티브 생성·파싱·로컬 호출 증거로 별도 확인.
- 계측 켬/끔 검증: 동일 계측 소스·모델에서 로깅 스위치만 변경한 의미적 응답 비교이며, 원본 엔진과의 동등성 실험은 아니다.

단위 검증이나 빌드 준비 성공을 공격 성공률 또는 모든 환경에서의 재현 성공으로 해석하지 않는다. 최종 실험 상태는 해당 실행의 원시 증거와 최종 보고서를 기준으로 한다.
